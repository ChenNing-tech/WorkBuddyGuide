# 搭建自己的 AI 工作台

个人工作台不是功能越多越好，而是把你每天会重复处理的材料、任务与判断集中到一个稳定入口。先做最小可用版本，再根据真实使用不断迭代。

本教程带你从零完成：选一个问题 → 整理材料 → 用 AI 做出最小版本 → 沉淀成 Skill，最终形成一个只属于你的稳定入口。

## 工作台长什么样

个人工作台通常有三种形态，可以由低到高逐步演进：

1. **文件夹工作台**：用一个目录集中存放材料、模板、提示词和备份，配一份 README 说明，零门槛；
2. **单文件首页**：一个双击就能打开的 `index.html`，把常用工具、常用提示词、模板和资料入口集中在一页；
3. **AI 工作台**：在 WorkBuddy 等工具中加载 Skill 与连接器，让 AI 按你的流程直接干活。

::: info 开始前需要准备
一台电脑、一个可用的 AI（如 [WorkBuddy](/bluebook/第一篇%20使用手册：先把%20WorkBuddy%20用起来/第%201%20章%20初识%20WorkBuddy/)），以及一件“你每周都做、最不想做”的事。
:::

## 第一步：选一个具体问题

好的起点通常具备三个条件：每周都会发生、有稳定输入、结果可以检查。例如：

- 汇总通知并转为待办
- 管理课程、学生与教学资料
- 整理会议记录并追踪后续事项
- 将备课材料生成可编辑的文档或演示稿
- 对项目文件进行分类、检索和版本记录

选定后，把下面的项目说明模板填写完整，它是后面所有步骤的输入：

```text
项目名称：
主要用户：
要解决的问题：
现有材料与数据：
最重要的一条工作流程：
必须人工确认的环节：
第一版验收标准：
需要保护的隐私或敏感信息：
```

::: tip 拿不准问什么
可以先用[提示词库](/prompts/)里的“苏格拉底式提问”，让 AI 帮你把问题问清楚，再回来填模板。
:::

## 第二步：整理材料，画出流程

1. 新建一个文件夹，把与这件事相关的所有文件（文档、表格、参考资料）集中放进去；
2. 列出数据的字段、分类和隐私边界，敏感信息单独标注；
3. 用一行文字画出核心流程：

```text
输入（材料/数据） → AI 处理 → 人工确认 → 保存 / 导出
```

::: warning 人工确认环节不能省
凡是会对外发出的内容——通知、成绩、评语、公开发布的文档——都必须保留人工确认步骤，AI 只起草，不代发。
:::

## 第三步：用 AI 做出最小版本

把第一步填好的项目说明粘贴进下面的提示词，交给 WorkBuddy 或任何 AI 工具执行：

```text
我要搭建一个个人 AI 工作台，我的情况如下：
【粘贴填好的项目说明模板】

请帮我完成：
1. 在当前目录创建 my-workbench 文件夹，包含子目录：docs、data、templates、skills、assets、backups；
2. 生成 README.md，写清项目目标、主要用户、最重要的一条工作流程和隐私边界；
3. 生成一个单文件首页 index.html，要求：
   - 双击即可在浏览器打开，不需要服务器；
   - 顶部显示项目名称和“最重要的一条工作流程”；
   - 分区展示：常用工具、常用提示词、模板文件、资料目录，每个条目是一个可点击的链接；
   - 样式简洁清楚，页面里不写任何个人隐私数据；
4. 告诉我首页最先放哪 3 个入口，并说明理由；
5. 完成后给出验收步骤，以及我明天可以做的第一个动作。
遇到必须由我决定的地方，停下来一次只问我一个问题。
```

执行完成后，你会得到这样一个可以直接使用的结构：

```text
my-workbench/
├─ README.md          # 项目目标与使用说明
├─ index.html         # 双击打开的工作台首页
├─ docs/              # 规则、教程和决策记录
├─ data/              # 结构化数据（避免提交隐私数据）
├─ templates/         # 可复用模板
├─ skills/            # 项目 Skill
├─ assets/            # 图片和附件
└─ backups/           # 本地备份
```

## 第四步：用真实材料跑通一次

1. 拿一份真实材料，按 README 里写的核心流程完整跑一遍；
2. 结果不满意时，告诉 AI 哪里不对，让它调整，不要自己接手重干；说不清原因时，可以说：“我现在讲不出来具体原因，但我就是不喜欢，请你对比几个方向，一次问我一个问题，帮我把判断标准找出来。”；
3. 一般 2～3 轮，这条流程就能稳定跑通。

第一版的验收标准很简单：流程能从头走到尾、结果可以检查、AI 知道在哪里停下来问你。

## 第五步：沉淀为提示词和 Skill

跑通之后，把经验固定下来，避免下次重新教 AI：

1. 把稳定的指令写成提示词模板，放进 `templates/`，并收录到[提示词库](/prompts/)的思路中；
2. 把整条流程做成 Skill，写清触发条件、输入、步骤、输出标准和人工确认点，参考 [Skill 技能](/skills/)的制作流程；
3. 把新入口挂到 `index.html` 首页，让工作台成为唯一入口。

## 第六步：持续迭代与分享

- 每周只加一个入口、修一条规则，不追求一次做全；
- 重要决定写进 `docs/` 的决策记录，方便回头看；
- 稳定复用一个月以上，再考虑分享给同事，或整理成 [Case](/community/case-contributing) 提交。

## 验收清单

- [ ] 一条核心流程可以从头跑通
- [ ] 首页只有一个入口，打开就知道今天从哪开始
- [ ] 页面与仓库中没有学生姓名、成绩等隐私数据
- [ ] 对外输出前有人工确认环节
- [ ] 至少沉淀了一个稳定提示词或 Skill
- [ ] 有备份目录，并实际备份过一次
